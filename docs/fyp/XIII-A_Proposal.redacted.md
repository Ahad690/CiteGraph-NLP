## 2. Project Title

**CiteGraph: Evidence-Grounded Citation-Graph Construction and Provenance
Analysis for Scientific Literature Using Cross-Provider Record Linkage**

## 3. Overall Scope (150 words)

Scientific literature is distributed across independent bibliographic
repositories, so the same work is indexed differently by each. Crossref, OpenAlex
and Europe PMC disagree on authorship, venue, and document type for a large
fraction of shared DOIs. Any analysis built on a single provider inherits that
provider's blind spots, and citation graphs assembled from raw counts cannot
distinguish a genuine link from a merge artifact.

This project builds a pipeline that resolves scholarly records across these
providers, links them with a confidence-scored matching layer, and constructs a
directed citation graph in which every edge carries an explicit provenance
record. A secondary component reads participant-flow diagrams from trial papers
to recover study-design metadata that is otherwise absent from bibliographic
sources. The system is evaluated for link precision against a manually verified
gold standard, and supports graph export and rank-based summarisation. Results
are reported per provider, so disagreements between sources stay visible.

## 4. Problem Statement and Gap

Bibliographic aggregators normalise records independently. The same DOI receives
different author lists, venue strings and publication types depending on which
index a tool queries, because each provider applies its own parsing heuristics
and corrects its own errors on its own schedule.

No provider is authoritative. Crossref favours publisher-deposited metadata,
OpenAlex applies its own author disambiguation, and Europe PMC is
domain-oriented, so no one of them is a superset of the others. Any analysis
built on a single index therefore inherits that index's blind spots. The
resulting merge errors are difficult to detect because they propagate rather
than surface: a faulty linkage inflates or deflates citation counts, corrupts
author trajectories, and introduces edges that no reviewer would accept. Most
systems make this worse by storing only an edge weight, so a downstream user
cannot distinguish a well-supported citation from an artifact of record linkage.

A separate gap concerns study-design metadata. CONSORT participant-flow
diagrams encode trial design rigorously, but that content lives inside figures,
and no bibliographic source exposes it. A system that recovers it would attach
trial structure to the same record that carries the citation data.

Prior systems address parts of this. None combine cross-provider record linkage
with per-edge provenance and recovered study-design metadata in one evaluated
pipeline.

## 5. Objectives

1. Implement DOI-based record resolution across Crossref, OpenAlex and Europe PMC
   with provider-specific fallback, rate-limit handling and retry policy.
2. Build a confidence-scored entity-matching layer that assigns each candidate
   link a score from author-set, venue and year agreement, and that surfaces
   ambiguous cases for manual review instead of forcing a decision.
3. Construct a directed citation graph in which every edge stores its provenance
   and link confidence alongside its weight.
4. Implement a vision pipeline that locates and reads CONSORT participant-flow
   diagrams to recover trial design metadata absent from bibliographic records.
5. Establish a manually verified gold standard and evaluate link precision
   against it, reporting negative and mixed results rather than aggregate-only
   scores.
6. Deliver a web interface for graph exploration, node inspection with full
   provenance, and export to standard interchange formats.

## 6. Methodology

The work follows a Pattern-B executable-workflow structure: semantic matching
decisions are separated from deterministic graph construction, so that ambiguous
decisions are reviewable and the deterministic stage is reproducible.

**Stage 1: Resolution.** A DOI is resolved against all three providers.
Provider records are normalised to a common schema. Failures are recorded as
explicit per-provider states rather than silently dropped.

**Stage 2: Linkage.** Records are matched on DOI first, then on fuzzy
bibliographic keys using `rapidfuzz` for edit-distance and
`rapidfuzz`-backed author-set overlap. Each candidate link receives a confidence
score. Links below threshold are retained as ambiguous rather than discarded.

**Stage 3: Provenance capture.** Every accepted link records which providers
agreed, which disagreed, the score, and the reason. This is what distinguishes
this system from a system that stores a bare integer.

**Stage 4: Graph construction.** Accepted links induce a directed citation
graph held in SQLite and exposed for traversal. Edge attributes carry provenance;
the graph never stores an un-attributed edge.

**Stage 5: Figure reading.** CONSORT participant-flow diagrams are located in
PDFs, segmented, and read with RapidOCR, an ONNX-exported PP-OCR model that runs
on CPU without a torch dependency. Extracted study-design fields are written
back onto the corresponding graph node.

**Evaluation.** A manually verified gold standard is constructed and link
precision measured against it. The evaluation is the deliverable, not a
formality: a precision number without a gold standard is not evidence.

## 7. Deliverables

1. **Resolution and linkage library** covering Crossref, OpenAlex and Europe PMC,
   with confidence scoring and explicit per-provider failure states.
2. **Provenance-aware citation graph** with SQLite persistence, traversal queries
   and export to standard citation formats.
3. **Figure-reading pipeline** recovering CONSORT participant-flow content into
   structured trial-design metadata, with RapidOCR/ONNX CPU inference.
4. **Evaluated system with gold standard and a web interface** comprising the
   measured link-precision report, a browsable graph with per-edge provenance
   visible, and a test suite enforcing the provenance invariant.

## 9. Risks and Limitations

| Risk | Mitigation |
|------|------------|
| Provider rate limits and outages | Per-provider retry with backoff; failures recorded as states, never as empty results |
| Ambiguous entity resolution | Ambiguous links retained and surfaced for review instead of silently resolved |
| OCR error on scanned figures | Confidence thresholding; low-confidence extractions are marked, not asserted |
| Emergent backend behavior | 273-test CI suite; a drift guard fails the build if the thesis and the code disagree |
| Evaluation overfitting | Gold standard is built independently of the system being evaluated |
