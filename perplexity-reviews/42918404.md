# Code Review: 42918404

> fix: centralized ID canonicalization and non-blocking SQLite concurrency

## Verdict
**NEEDS WORK** — the commit introduces `IdCanonicalizer` and wraps SQLite calls in `anyio.to_thread` for concurrency, but there are gaps in ID normalization, SQLite multi-thread safety, and async correctness that prevent the system from fully achieving non-blocking and robust canonicalization.

## Implementation vs Intent Gap
- **Centralized ID canonicalization**: `IdCanonicalizer` provides `canonicalize()` and `to_openalex_id()` (`ids.py:L1-L57`) and replaces previous ad-hoc normalization in `input/normalizer.py` and `providers/openalex.py`. ✅ Core logic is centralized.  
- **Non-blocking SQLite storage**: `routes.py` wraps `SQLiteStore` calls in `anyio.to_thread.run_sync` (`routes.py:L38,L46,L59,L82,L108,L132,L133,L141`), which allows blocking I/O without freezing the event loop. ⚠️ Only partially safe: SQLiteStore still uses a threading.Lock (`sqlite.py:L12`) with per-call connections; simultaneous heavy writes may still serialize and block threads, defeating true concurrency.  
- **Timestamp ambiguity**: Markdown exports now parse ISO timestamps with Z→+00:00 replacement (`routes.py:L143-L147`). ✅ Resolves naive UTC ambiguity for display.

Gaps:
- `IdCanonicalizer` assumes numeric strings are PMIDs (`ids.py:L29-L31`), which may misclassify other numeric identifiers.  
- `to_openalex_id()` may return unsupported ID formats if `canonicalize()` outputs unexpected strings (`ids.py:L54-L57`).  
- SQLite connection per call + lock may become a bottleneck under high concurrency; true async DB drivers not used.

## Missing Changes
- Other provider classes (Europe PMC, PubMed, ClinicalTrials) still do not use `IdCanonicalizer`; inconsistent ID normalization remains (`providers/*.py`).  
- No migration or handling for legacy stored run results using old in-memory ID formats (`routes.py` + `sqlite.py`).  
- No async SQLite connection pooling; `anyio.to_thread` only shifts blocking, does not fully prevent bottlenecks under many simultaneous requests.  
- Input validation on `paper_id` or `query.value` is still missing before canonicalization.  

## Security & Data Integrity
- **Silent data corruption / incomplete graphs**: misclassified numeric IDs or malformed IDs (`ids.py:L29-L31,L54-L57`) can produce missing references without raising errors.  
- **Thread contention / DoS**: `_lock` in SQLiteStore (`sqlite.py:L12`) serializes all writes; multiple simultaneous background runs may stall, delaying updates and exposing clients to inconsistent run status.  
- **False confidence / report misalignment**: if canonicalization fails silently, Markdown/CSV reports may display wrong IDs or empty papers (`routes.py:L143-L157`).  

## Score: 6/10
The commit centralizes ID normalization and adds non-blocking wrappers for SQLite, which are meaningful improvements. However, numeric ID assumptions, fallback logic for `to_openalex_id()`, and serialized SQLite access under high concurrency leave the system at risk of silent failures and contention. True async safety, cross-provider canonicalization, and input validation remain incomplete.
