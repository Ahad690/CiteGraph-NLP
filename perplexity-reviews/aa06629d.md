# Code Review: aa06629d

> Repair broken Nginx config: clean up nested citegraph block

## Summary

This commit attempts to repair prior broken Nginx mutations by using a Python script inside `.github/workflows/deploy-backend.yml` to clean all old CiteGraph proxy state, remove duplicate `citegraph-proxy.conf` includes, remove existing `location /citegraph/` blocks via brace matching, and insert a clean `/citegraph/` block after the `/penora/` block. It also adds a timestamped backup, removes the stale include file, validates with `nginx -t`, reloads Nginx, and now correctly exits with failure if no matching Nginx config is found (`.github/workflows/deploy-backend.yml:L104-L182`).

## Issues & Suggestions

- **Positive: this is a much better recovery strategy than previous `sed`/`awk` edits**  
  The script explicitly removes old include lines and previous `/citegraph/` blocks before inserting a single clean block (`.github/workflows/deploy-backend.yml:L119-L145`). That directly addresses the known broken nested `/penora/` state and duplicate includes.

- **Still prints full Nginx config to deploy logs**  
  `cat "$NGINX_CONF"` remains at `.github/workflows/deploy-backend.yml:L177`. This is helpful while debugging, but risky long-term because Nginx configs can expose internal routes, certificate paths, upstreams, and operational structure. Remove after confirming the fix, or print only the `/penora/` and `/citegraph/` snippets.

- **No rollback if `nginx -t` fails**  
  The workflow creates a backup at `.github/workflows/deploy-backend.yml:L111`, but if `nginx -t` fails at `.github/workflows/deploy-backend.yml:L178`, the broken config remains on disk. Add a restore step like `cp "$BACKUP" "$NGINX_CONF"` on validation failure.

- **Insertion depends on `/penora/` existing**  
  The Python script inserts `/citegraph/` only after finding `location /penora/` (`.github/workflows/deploy-backend.yml:L154-L166`). If the Penora location is renamed, moved to an included file, or absent, the script writes a config with no CiteGraph block and only prints `WARN: /penora/ block not found` (`.github/workflows/deploy-backend.yml:L170`). That should be treated as deployment failure, not warning, because the frontend depends on `/citegraph/`.

- **Brace matching is adequate but not a real Nginx parser**  
  The brace-based removal at `.github/workflows/deploy-backend.yml:L125-L135` should work for simple Nginx blocks, but it can still be fooled by braces in comments or unusual formatting. It is acceptable as a repair script, but a dedicated managed include file is still preferable once the server config is stable.

- **Good: Nginx variables are preserved safely**  
  Because the proxy block is generated inside Python string literals, `$host`, `$remote_addr`, `$proxy_add_x_forwarded_for`, and `$scheme` are written literally (`.github/workflows/deploy-backend.yml:L146-L154`). This fixes the shell expansion risk from the earlier `sed` version.

- **Config discovery is narrower now**  
  `NGINX_CONF` only searches `/etc/nginx/sites-enabled/` (`.github/workflows/deploy-backend.yml:L106`). Previous versions also checked `/etc/nginx/conf.d/` and `/etc/nginx/nginx.conf`. If this server definitely stores the domain config in `sites-enabled`, this is fine; otherwise this can fail unnecessarily.

## Security & Performance

Security is improved by repairing a broken proxy route and keeping the backend behind `127.0.0.1:8002` (`.github/workflows/deploy-backend.yml:L149`). The remaining security concern is full config logging (`.github/workflows/deploy-backend.yml:L177`). Performance impact is negligible; this is a deploy-time file edit and Nginx reload only. Operational reliability is better than prior commits, but rollback on failed validation is still needed.

## Overall Score: 8/10

This is a practical repair commit that directly addresses the broken nested-location state and duplicate includes. It is significantly more robust than the earlier attempts, but it should not be considered fully production-safe until it rolls back on `nginx -t` failure, fails when insertion does not happen, and removes full config dumps from deploy logs.

## Recommendations

1. Store the backup path in a variable and restore it if `nginx -t` fails.  
2. Make `WARN: /penora/ block not found` a hard failure with `exit 1`.  
3. Remove or narrow `cat "$NGINX_CONF"` after this diagnostic deploy succeeds.  
4. Expand config discovery back to `/etc/nginx/conf.d/` if the server layout is not guaranteed.  
5. Add a final health check for `https://hetzner-api.duckdns.org/citegraph/health` after reload.
