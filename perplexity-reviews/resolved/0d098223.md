# Code Review: 0d098223

> fix: implement persistent storage, request limits, and robust ID handling

## Verdict
**NEEDS WORK** — persistent storage and request limits are partially implemented, but multiple gaps remain in ID handling, concurrency, and export fidelity that leave the system vulnerable to silent failures and data inconsistencies.

## Implementation vs Intent Gap
- **Persistent storage**: Added SQLite-backed `SQLiteStore` (`sqlite.py:L1-L65`) and replaced in-memory caches with database calls (`routes.py:L13-L56`). ✅ Works for single-threaded use, but the code opens a new connection per call, which may not be safe under concurrent requests.  
- **Request limits**: `start_run()` clamps `backward_depth`, `forward_depth`, and `max_total_papers` (`routes.py:L30-L32`). ✅ Limits are enforced but are hardcoded and may still allow costly background tasks for edge cases.  
- **OpenAlex ID handling**: `get_references()` and `get_citations()` now cover DOI, pmid, W-prefixed IDs, and some URL cases (`openalex.py:L98-L136`), but fallback logic still risks constructing invalid IDs for malformed input (e.g., arbitrary strings not matching any known prefix). ⚠️  
- **Export fidelity**: `/export/csv` and `/export/markdown` now generate structured outputs (`routes.py:L117-L157`), but CSV output is simplified; no streaming support and population evidence may not match edge cases. ⚠️

## Missing Changes
- Connection pooling or single persistent DB connection not used in `SQLiteStore` (`sqlite.py:L1-L65`), which is important for multi-worker Uvicorn/Gunicorn setups.  
- Run ID propagation to orchestrator remains unverified for multi-call scenarios (`routes.py:L45`).  
- Other providers (Europe PMC, PubMed, ClinicalTrials) still unimplemented; their ID handling is not aligned with the SQLite storage approach.  
- No validation or sanitization of `paper_id` before storing/executing queries, allowing potentially malformed IDs to propagate through storage and API calls.  

## Security & Data Integrity
- **Silent scientific corruption**: malformed OpenAlex IDs (`openalex.py:L98-L136`) may cause references or citations to be dropped without error, producing incomplete graphs.  
- **Race conditions / data loss**: separate SQLite connections for create/update may result in overwrites or lost run status if two requests modify the same run_id simultaneously.  
- **DoS potential**: background tasks still run CPU/IO-heavy traversal; SQLite operations are blocking, risking thread starvation under load.  
- **Timestamp ambiguity**: naive UTC timestamps may cause reports to display inconsistent `created_at`/`updated_at` in Markdown exports (`routes.py:L144-L157`).  

## Score: 6/10
The commit makes tangible progress by introducing SQLite persistence, request clamping, and improved ID handling. However, the ID fallback logic is still fragile, concurrency is unsafe due to per-call SQLite connections, and exports remain partially incomplete. These gaps allow silent data corruption, DoS, and inconsistent run tracking, meaning the stated “robust ID handling and persistent storage” claim is only partially realized.
