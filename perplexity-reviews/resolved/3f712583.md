# Code Review: 3f712583

> Set VITE_API_BASE to Hetzner backend in frontend deploy

## Summary

This commit updates the CI/CD pipeline for the frontend (`.github/workflows/deploy-frontend.yml:L28`) to set the environment variable `VITE_API_BASE` to the Hetzner backend URL (`http://46.225.8.77:8002`) during the build. Previously, the frontend deployed to Firebase defaulted to `localhost:8000`, which caused it to fail to reach the production backend. This ensures that the built SPA connects to the correct live backend.

## Issues & Suggestions

- **Hardcoded Backend URL**: `VITE_API_BASE` is set to a fixed IP (`http://46.225.8.77:8002`) on `deploy-frontend.yml:L29`. This works, but using an IP can be brittle:
  - If the backend IP changes, the frontend build will break.
  - Consider using a DNS hostname (e.g., `https://api.citegraph-nlp.com`) to avoid redeploying frontend for backend IP changes.
  
- **Environment Separation**: The current setting is global for all environments. You may want a more flexible approach:
  - Use `VITE_API_BASE` differently for `development`, `staging`, and `production`.
  - For example, read it from a secret or configuration file in GitHub Actions rather than hardcoding.

- **Security of Plain HTTP**: The URL is `http://`, not `https://`. Deploying over plain HTTP exposes traffic to interception. Consider using HTTPS in production.

- **Cache Busting / Deployment Artifacts**: Ensure that the frontend build is invalidated if `VITE_API_BASE` changes; otherwise, clients may get an old version pointing to the wrong backend.

## Security & Performance

- **Security**: Using plain HTTP exposes API requests and tokens to MITM attacks. Sensitive data in requests should use HTTPS.
- **Performance**: No performance impact, only the build-time environment is affected.
- **Scalability**: Hardcoding IP reduces flexibility if scaling backend behind a load balancer or multiple instances.

## Overall Score: 8/10

The commit solves a critical production bug (frontend pointing to localhost) but introduces maintainability and security concerns by hardcoding a plain HTTP IP address.

## Recommendations

1. Replace the IP address with a stable DNS name (e.g., `https://api.citegraph-nlp.com`) for flexibility and HTTPS support.  
2. Consider storing `VITE_API_BASE` in GitHub Actions secrets or environment-specific `.env` files to allow per-environment builds.  
3. Ensure the backend supports HTTPS and update the frontend to use `https://` in production to secure traffic.  
4. Optionally, add a CI check to verify that `VITE_API_BASE` is set and reachable before deploying.  
5. Document the purpose of `VITE_API_BASE` in README / USER_GUIDE.md for future maintainers.  

This commit fixes the immediate deployment problem but could be hardened for security and long-term maintainability.
