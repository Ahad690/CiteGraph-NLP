# Code Review: 4159c7e2

> fix: fully async aiosqlite storage and strict ID classification

## Verdict
**NEEDS WORK** — the migration to `aiosqlite` and stricter numeric ID constraints improves async behavior and canonicalization, but edge-case ID misclassification, potential blocking on DB connections, and incomplete provider integration leave the system only partially robust.

## Implementation vs Intent Gap
- **Fully async aiosqlite storage**: `SQLiteStore` now uses `async def` methods with `aiosqlite.connect()` (`sqlite.py:L14-L55`) and `await` calls in routes (`routes.py:L46,L50,L63,L87,L112,L136,L137,L145`). ✅ True async I/O instead of thread wrapping.  
- **Strict numeric ID classification**: `IdCanonicalizer` now limits PMIDs to 1–9 digit numeric strings and OpenAlex IDs to W-prefixed (`ids.py:L28-L36`). ✅ More rigorous than previous commit.  
- **DB startup initialization**: `@router.on_event("startup")` calls `store._init_db()` (`routes.py:L42-L46`). ✅ Ensures tables exist before first request.  

Gaps:
- `IdCanonicalizer.to_openalex_id()` may still produce unsupported IDs for malformed input like raw URLs or unconventional prefixes (`ids.py:L51-L60`).  
- `aiosqlite.connect()` still opens a new connection per method call (`sqlite.py:L17,L25,L34,L43,L52`)—this could cause overhead under high concurrency; no connection pooling implemented.  
- Fallback DOI handling in `to_openalex_id()` overlaps with canonicalization logic (`ids.py:L57`), potentially duplicating `doi:` prefix in rare cases.

- No connection pooling or shared async connection; under heavy load, concurrent writes may still serialize or fail due to SQLite locking.

## Security & Data Integrity
- **Silent scientific corruption**: misclassified IDs may drop or misassign citations, producing incomplete or misleading graphs (`ids.py:L28-L36,L51-L60`).  
- **DB contention / latency spikes**: per-call `aiosqlite.connect()` without pooling may cause blocking under multiple async background runs, delaying status updates (`sqlite.py:L17,L25,L34,L43,L52`).  
- **Partial failures**: exceptions in `create_run` or `save_result` may leave a run in `started` status without results, creating inconsistent system state (`routes.py:L46,L63,L112`).
