> fix: persistent DB connections, input validation, and EuropePMC integration

## Verdict
**NEEDS WORK** — the commit introduces persistent `aiosqlite` connections, input validation, and a working EuropePMC provider, but incomplete connection lifecycle handling, potential null `_db` references, and partial input validation leave the system vulnerable to runtime errors and inconsistent provider behavior.

## Implementation vs Intent Gap
- **Persistent DB connections**: `SQLiteStore` now stores a single `_db` connection (`sqlite.py:L14-L22`) and exposes `connect()` and `close()` (`sqlite.py:L16-L26`). ✅ Single persistent connection replaces per-call connections.  
- **Input validation**: `PaperQuery` adds `field_validator` for non-empty `value` (`paper.py:L13-L18`). ✅ Prevents empty queries.  
- **EuropePMC integration**: `MetadataResolver` appends `EuropePMCProvider()` when enabled (`resolver.py:L18,L20`), and `EuropePMCProvider.resolve()` queries the real API (`europe_pmc.py:L24-L56`). ✅ Functional provider implementation.  

Gaps:
- `_db` is never checked for `None` in methods like `create_run()`, `update_status()`, `save_result()`, or `get_run()` (`sqlite.py:L27-L57`). Calling these before `connect()` will raise exceptions.  
- `EuropePMCProvider` does not validate input beyond `IdCanonicalizer.canonicalize()` (`europe_pmc.py:L25-L45`); malformed `query.value` may still produce invalid API calls.  
- No retry/backoff or exception handling for failed `aiosqlite` writes in background tasks; a DB connection failure could abort a run silently.  
- Input validation only ensures non-empty `value`; it does not enforce type, prefix, or format constraints for DOI/PMID/PMCID (`paper.py:L13-L18`).
