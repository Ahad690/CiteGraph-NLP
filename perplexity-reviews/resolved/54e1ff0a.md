# Code Review: 54e1ff0a

> feat: initial implementation of confidence-aware citation lineage and knowledge graph backend

## Verdict


**FAIL** — this is not a working backend pipeline: the first end-to-end run can crash, citation traversal is wired to invalid IDs, run state is non-persistent and inconsistent, and major advertised modules are absent.


## Implementation vs Intent Gap


The diff adds a large amount of documentation and scaffolding, but the actual backend is thin and internally inconsistent:


- **The API cannot reliably complete a run.** `PipelineOrchestrator.run()` instantiates `Study` at `src/citegraph/pipeline/orchestrator.py:L51`, but `Study` is never imported in that file. The first paper loop hits `NameError`.
- **Citation traversal is effectively broken for DOI-seeded papers.** `MetadataMerger` chooses the DOI as `paper_id` when available at `src/citegraph/metadata/merger.py:L24`, but `OpenAlexProvider.get_references()` blindly calls `/works/W{paper_id}` at `src/citegraph/providers/openalex.py:L94`. For DOI paper IDs this becomes `/works/W10...`; for OpenAlex IDs already like `W274...`, it becomes `WW274...`. OpenAlex work IDs already include the `W` prefix, and external DOI lookups use `doi:` or full DOI URLs, not a fabricated `W` prefix. [OpenAlex Developers](https://developers.openalex.org/guides/get)
- **OpenAlex author parsing is wrong.** `_map_to_paper()` reads `data.get("memberships", [])` at `src/citegraph/providers/openalex.py:L64`, but OpenAlex work records expose authors under `authorships`. [OpenAlex Developers](https://developers.openalex.org/api-reference/works/get-a-single-work)
- **No durable run backend exists.** `results_cache` is a process-local dict at `src/citegraph/api/routes.py:L12`. Restarts, multiple Uvicorn workers, or deployment scaling lose or split all run data.
- **The run ID returned to the client is not the run ID inside the result.** `start_run()` creates `run_id` at `src/citegraph/api/routes.py:L22`, while `PipelineOrchestrator.run()` creates a different UUID at `src/citegraph/pipeline/orchestrator.py:L37`. The cached key and returned `RunResult.run_id` diverge.
- **Export endpoints are documented but not implemented.** `README.md` advertises `/api/runs/{run_id}/export/json`, `/csv`, `/graphml`, and `/markdown`, but `src/citegraph/api/routes.py` only implements `/runs`, `/runs/{run_id}`, and `/runs/{run_id}/graph`.
- **PDF parsing, GROBID integration, Europe PMC, PubMed, ClinicalTrials, Neo4j, SQLite cache, provenance-rich storage, and legal access checks are mostly config/doc promises, not implemented code.**

## Security & Data Integrity


- **Cross-origin credential exposure risk:** `src/citegraph/api/main.py:L16-L18` configures wildcard origins with credentials. If authentication cookies or bearer-token browser flows are later added, arbitrary origins become part of the trust boundary, and the current config is explicitly disallowed by FastAPI’s CORS guidance. [FastAPI](https://fastapi.tiangolo.com/tutorial/cors/)
- **Unbounded API-amplification / denial-of-service:** `src/citegraph/api/routes.py:L14-L18` accepts traversal depth and max paper count with no upper bounds. A single POST can cause the server to launch a same-process background task that fans out to OpenAlex/Crossref repeatedly. Because errors are swallowed and status is not tracked, operators and clients get poor visibility into abuse.
- **Data poisoning via wrong paper identity:** `src/citegraph/providers/openalex.py:L37-L40` accepts the first title-search result; `src/citegraph/metadata/merger.py:L51-L64` then assigns high confidence (`0.95` when multiple providers exist, `0.8` otherwise). A near-title collision can produce a convincing but wrong citation graph and population extraction.
- **Cross-run contamination:** `src/citegraph/graph/builder.py:L8-L12` reuses the same NetworkX graph. One user’s run can bleed nodes and edges into another user’s result when served through the global orchestrator at `src/citegraph/api/routes.py:L9`.
- **Silent scientific corruption:** The OpenAlex ID bug means many runs produce missing or partial citations without an explicit warning. The output can look “completed” while omitting the core citation lineage.
- **No tenant isolation:** `GET /api/runs/{run_id}` at `src/citegraph/api/routes.py:L46-L50` exposes any cached run to anyone who knows or guesses the UUID. There is no user binding, auth, or access control.
