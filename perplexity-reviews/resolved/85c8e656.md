# Code Review: 85c8e656

> fix: strict ID validation, graceful shutdown, and lazy DB connections

## Verdict
**NEEDS WORK** — the patch improves some paths, but it does not fully realize the claimed behavior and it introduces new shutdown and validation edge cases.

## Implementation vs Intent Gap
The identifier checks in `src/citegraph/models/paper.py:L8-L26` only cover `doi`, `pmid`, and `pmcid`; `title` and `url` still accept any non-empty string, so the “strict ID validation” claim is only partially true. The graceful-shutdown work in `src/citegraph/api/routes.py:L52-L63` switches from FastAPI-managed background tasks to raw `asyncio.create_task`, but it never cancels, awaits, or removes completed tasks from `active_tasks`, so the shutdown story is incomplete. The SQLite hardening in `src/citegraph/storage/sqlite.py:L16-L73` adds `_ensure_connection()`, but it depends on callers having run `connect()` first; the code does not guarantee that invariant anywhere in this diff.

## Missing Changes
- `src/citegraph/api/routes.py:L52-L63` should add a shutdown hook that cancels or awaits `active_tasks`; right now it only creates the tracking set and never uses it for teardown.
- `src/citegraph/api/routes.py:L59-L63` should remove completed tasks from `active_tasks` with a done callback; otherwise the tracking set is not a real lifecycle manager.
- `src/citegraph/api/routes.py:L81-L88` should not swallow the second failure path in `update_status`; that hides storage corruption and prevents operators from detecting failed writes.
- `src/citegraph/models/paper.py:L15-L26` should validate all `query_type` variants symmetrically, especially `title` and `url`, instead of leaving them as generic non-empty strings.
- `src/citegraph/models/paper.py:L15-L26` should avoid relying on `info.data.get('query_type')` unless field order is guaranteed or the check is moved to a model-level validator; Pydantic explicitly warns that `ValidationInfo.data` only includes already-validated fields.
- `src/citegraph/storage/sqlite.py:L19-L74` should make connection initialization explicit at the API boundary, not only inside the storage class, because the rest of the code still assumes the store is ready.
- `src/citegraph/providers/europe_pmc.py:L20-L39` still needs a supported path for `url` queries or a deliberate rejection earlier in validation, otherwise the provider surface remains inconsistent.

## Security & Data Integrity
The worst case is silent run corruption: a background task can be detached, the DB connection can close underneath it, and the failure path can be swallowed, leaving a paper analysis marked neither successful nor failed while data writes never land. The weak tracking plus raw `asyncio.create_task` means the server can shut down with in-flight writes half-complete, and SQLite state can end up inconsistent or missing the final result row. The validation logic also risks accepting malformed identifiers, so downstream provider calls can fetch the wrong record or no record at all, producing incorrect citation data that looks valid to callers. Pydantic’s field-order dependency makes the `query_type`-aware validator brittle enough that a later refactor of field order could change accepted inputs without an obvious code change.

## Score: 4/10
The diff does add a real connection guard and some narrower ID checks, but the shutdown mechanism is not actually completed and the error-handling changes mostly hide failures instead of resolving them. The main evidence is the fire-and-forget task creation in `src/citegraph/api/routes.py:L59-L63`, the swallowed update failure in `src/citegraph/api/routes.py:L84-L88`, and the order-sensitive cross-field validation in `src/citegraph/models/paper.py:L15-L26`.
