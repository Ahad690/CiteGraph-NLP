> Add scipy: required by networkx.pagerank in v3.x

## Summary

This commit adds `scipy` to `requirements.txt` to fix runtime failures in the foundational paper ranking pipeline when calling NetworkX PageRank. The change is minimal and directly addresses the reported crash: `No module named 'scipy'` (`requirements.txt:L14`). This is a dependency correctness fix for environments using NetworkX 3.x behavior where SciPy-backed numerical routines are expected for PageRank execution.

## Issues & Suggestions

- **Good fix: missing runtime dependency is now declared**  
  Adding `scipy` at `requirements.txt:L14` is the correct immediate fix if the deployed code path uses `networkx.pagerank` and the current NetworkX version requires SciPy in your environment.

- **Dependency is unpinned**  
  `requirements.txt:L14` adds bare `scipy`, matching the existing style, but SciPy wheels can vary significantly by Python version, OS, and architecture. To improve reproducibility, consider pinning or constraining it, for example `scipy>=1.10,<2`, aligned with your Python version and Docker base image.

- **Build image size and install time will increase**  
  `requirements.txt:L14` introduces a large scientific dependency. This is acceptable if PageRank requires it, but expect slower Docker builds and larger images. If image size matters, confirm the base image supports SciPy wheels so CI does not compile from source.

- **Consider adding a regression test for ranking**  
  The missing dependency surfaced only at runtime. Add a small test that runs the foundational ranking/PageRank pipeline on a tiny graph and asserts no import/runtime error. This would catch future dependency drift.

- **Document why SciPy is present**  
  Since SciPy is not otherwise obviously used in the diff, a comment is not possible in `requirements.txt` unless the project allows comments there. Consider documenting this in dependency notes or adding a nearby test name that makes the requirement obvious.

## Security & Performance

- **Security:** No direct security concern, but adding a large dependency increases supply-chain surface area. Keep dependency scanning enabled.  
- **Performance:** PageRank execution should be more robust and likely faster with SciPy-backed linear algebra, but install/build time and container size will increase.  
- **Scalability:** This is a positive change for graph analytics scalability, assuming SciPy wheels are available in production.

## Overall Score: 9/10

This is a correct and focused fix for a real production crash. The only concerns are reproducibility and deployment cost from adding an unpinned heavy dependency.

## Recommendations

1. Add a small PageRank/foundational-ranking regression test.  
2. Pin or constrain `scipy` to a known-compatible version range.  
3. Verify Docker/CI installs SciPy from wheels, not source builds.  
4. Run dependency vulnerability scanning after adding SciPy.
