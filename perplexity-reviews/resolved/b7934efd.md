# Code Review: b7934efd

> Fix Nginx citegraph route: use include file instead of awk injection

## Summary

This commit improves the backend deployment workflow by replacing fragile inline `awk` location-block injection with a cleaner Nginx include-file approach. The workflow now writes `/etc/nginx/citegraph-proxy.conf` containing the `/citegraph/` reverse proxy block, then inserts `include /etc/nginx/citegraph-proxy.conf;` into the Nginx server config for `hetzner-api.duckdns.org` if not already present (`.github/workflows/deploy-backend.yml:L105-L129`). This is a meaningful reliability improvement over editing nested braces directly.

## Issues & Suggestions

- **Good improvement: include file is much safer than brace injection**  
  `.github/workflows/deploy-backend.yml:L107-L116` writes the route as a standalone Nginx snippet instead of mutating nested server-block braces. This is much easier to audit and less likely to corrupt the main config.

- **Missing failure when Nginx config is not found**  
  If `NGINX_CONF` is empty, the script still runs `nginx -t && systemctl reload nginx` and prints `"Nginx citegraph route configured"` (`.github/workflows/deploy-backend.yml:L119-L129`). In that case the snippet exists but is not included anywhere, so the deploy appears successful while `/citegraph/` remains unreachable. This should fail the workflow or at least emit a clear warning and skip the success message.

- **`sed` insertion can affect multiple server blocks**  
  The command inserts after every matching `server_name.*hetzner-api` line (`.github/workflows/deploy-backend.yml:L121`). If the config has both HTTP and HTTPS server blocks for the same domain, the include may be inserted into both. That may be acceptable, but it should be intentional. Prefer targeting the TLS server block or using a dedicated include directory already loaded by the desired server.

- **No backup or rollback on invalid Nginx config**  
  The workflow modifies the live config before running `nginx -t` (`.github/workflows/deploy-backend.yml:L121-L128`). If the test fails, the deployed config file remains broken even though Nginx may keep serving the old config in memory. Add a backup and rollback path around the edit.

- **Idempotency check is reasonable but broad**  
  `grep -q 'citegraph-proxy' "$NGINX_CONF"` (`.github/workflows/deploy-backend.yml:L120`) avoids duplicate includes, but it could produce false positives from comments or unrelated text. A stricter check like `grep -q 'include /etc/nginx/citegraph-proxy.conf;'` would be safer.

- **Proxy behavior is correct for prefix stripping**  
  `location /citegraph/` plus `proxy_pass http://127.0.0.1:8002/;` (`.github/workflows/deploy-backend.yml:L108-L109`) correctly strips the `/citegraph/` prefix before forwarding to the backend. This should map `/citegraph/health` to `/health`, which matches the frontend `VITE_API_BASE` pattern.

## Security & Performance

Security-wise, this is an improvement because it enables HTTPS access through the existing Nginx frontend and avoids mixed-content issues. The proxy forwards only to `127.0.0.1:8002`, which is appropriate (`.github/workflows/deploy-backend.yml:L109`). Performance impact is negligible; the Nginx reverse proxy adds minimal overhead. The main operational risk is configuration drift or a failed edit leaving the Nginx config on disk invalid.

## Overall Score: 8.5/10

This is a solid direction and much more maintainable than previous `awk`/brace insertion attempts. The score is held back by missing failure handling when no config is found, no backup/rollback around live config edits, and broad insertion/idempotency matching.

## Recommendations

1. Fail the deploy if `NGINX_CONF` is empty instead of printing success.  
2. Back up `$NGINX_CONF` before `sed`, run `nginx -t`, and restore on failure.  
3. Use a stricter idempotency check for the exact include directive.  
4. Add a post-deploy health check for `https://hetzner-api.duckdns.org/citegraph/health`.  
5. Consider using an Nginx `conf.d` include directory that is already referenced by the server block, avoiding `sed` entirely.
