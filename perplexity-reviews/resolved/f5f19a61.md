# Code Review: f5f19a61

> Fix dashboard crash when run is still processing or failed

## Summary

This commit fixes a dashboard crash in `RunStatusCard` when the API returns a lightweight `RunStatus` payload for in-progress or failed runs instead of a full `RunResult`. The component previously guarded `run` but not `run.papers`, so failed or processing states could still call `.find()` on `undefined`. The fix updates the lookup to `run?.papers?.find(...)`, making the sidebar resilient to partial run payloads.

## Issues & Suggestions

- **Good targeted crash fix**  
  `frontend/src/components/layout/RunStatusCard.tsx:L22` correctly changes `run?.papers.find(...)` to `run?.papers?.find(...)`. This directly addresses the reported failure mode where `run` exists but `papers` does not.

- **Comment clearly documents the API shape mismatch**  
  `frontend/src/components/layout/RunStatusCard.tsx:L19-L21` explains that processing/failed API responses may omit `papers`. This is useful context for future maintainers and makes the optional chaining intentional rather than defensive noise.

- **Type model likely needs tightening**  
  `frontend/src/components/layout/RunStatusCard.tsx:L22-L23` suggests `run` is typed broadly enough to allow both `RunResult` and `RunStatus`, but the component still accesses `run.seed_paper_id` and `run.status`. Consider making the prop type an explicit union like `RunResult | RunStatus` so TypeScript forces guards for fields that only exist on completed runs.

- **Consider normalizing at the API boundary instead of per-component guards**  
  `frontend/src/components/layout/RunStatusCard.tsx:L22` fixes this one crash, but similar failures can recur anywhere a component assumes `papers`, `citation_edges`, or `ranked_*` arrays exist. If not already done globally, normalize partial run responses in the hook/API layer so UI components receive a consistent shape.

- **Potential fallback display should be verified**  
  `frontend/src/components/layout/RunStatusCard.tsx:L22` now makes `seedPaper` `undefined` safely. Review the JSX below this line to ensure the card renders a useful failed/processing state when `seedPaper` is absent, rather than showing blank title/metadata.

## Security & Performance

No security concerns. Performance impact is negligible; optional chaining adds no meaningful overhead. Reliability improves because the sidebar no longer crashes the entire dashboard for failed or still-processing runs.

## Overall Score: 9/10

This is a small, correct, high-impact fix for a real production crash. The only reason it is not a 10 is that it treats one symptom locally; the broader API shape mismatch should be captured in shared types or normalized in the data layer.

## Recommendations

1. Add a regression test for `RunStatusCard` with `{ run_id, status, error }` and no `papers`.  
2. Define a proper `RunStatus | RunResult` union type for dashboard run data.  
3. Normalize partial run payloads in `useRun` or the API client to reduce repeated optional guards across components.
