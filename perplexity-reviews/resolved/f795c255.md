> fix: atomic SQLite locking, centralized TaskManager, and robust URL parsing

## Verdict
**NEEDS WORK** — The commit partially implements atomic SQLite access, centralized task management, and improved URL parsing, but gaps in lock coverage, task registration, and regex reliability create real concurrency, shutdown, and data extraction risks.

## Implementation vs Intent Gap
- `SQLiteStore` adds `_lock` around most write methods (create_run, update_status, save_result) but **does not consistently protect all future reads/writes**, e.g., `_execute_with_retry` exists but is unused (L49).  
- `TaskManager` only tracks tasks registered via `start_run` (routes.py L69), leaving **other background tasks potentially unmanaged**, violating the claimed “centralized TaskManager for lifecycle control.”  
- URL parsing in `EuropePMCProvider` attempts DOI/PMID extraction (providers/europe_pmc.py L33+), but **query parameters or edge URL formats may fail**, and there’s no validation that `cid` is a well-formed URL.

## Missing Changes
- All `SQLiteStore` methods, especially future query helpers, must use `_lock` or `_execute_with_retry` consistently.  
- Background tasks created outside `start_run` should also be registered with `task_manager` to enforce proper shutdown.  
- URL parsing in `EuropePMCProvider` should normalize the full URL (scheme, netloc, query) and robustly handle edge cases.  
- Consider **timeouts and exception handling** in `execute_run` tasks for safe shutdown.

## Security & Data Integrity
- Unlocked concurrent writes to SQLite could cause **database corruption**, missing run records, or inconsistent statuses.  
- Unregistered background tasks may continue after shutdown, potentially **mutating state after services close**, leading to corrupted results or partial runs.  
- Incorrect DOI/PMID parsing may store invalid metadata, **propagating errors through the pipeline** or indexing wrong papers.
